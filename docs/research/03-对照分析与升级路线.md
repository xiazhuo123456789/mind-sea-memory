## 1. 对照表（方向 A-J × 八问）

### A. 人类认知启发的记忆机制

| 问 | 答 |
| --- | --- |
| 论文怎么实现 | Generative Agents：memory stream + 反思树；LightMem：Atkinson-Shiffrin 三阶段；MSR 2026：engram 成熟、干扰遗忘、再巩固 |
| 解决什么 | 记忆有层次（事件→模式→洞察）、会老化、会互相干扰 |
| 现状 | **部分实现**：retention 衰减 ✓、nightly ✓、digest ✓；❌ 无 working memory 层、无反思树、无干扰衰减、无洞察 kind |
| 不足 | 缺"事件→模式→洞察"的递归抽象；碎事件永远只是碎事件 |
| 能否引入 | ✅ 反思（P1）、干扰衰减（P2）；工作记忆层（P2，需改 /v1 注入策略） |
| 需改代码 | lib/extract+server（insight kind 与 evidence）、nightly（干扰项）、新模块 lib/reflect.mjs |
| 预期提升 | 长期交互后能回答"他为什么开始那个项目"级别的模式问题 |
| 风险 | 反思质量依赖 LLM；洞察可能失真——必须可溯源（insight 带 source_ids）+ 人工抽查 |

## 2. 升级路线（P0 / P1 / P2）

### P0 —— 必须改进（修"机制存在但没接线"与证据链）

| # | 任务 | 实现 | 验收标准 |
| --- | --- | --- | --- |
| P0-1 | **原始事件落库 + 证据链** | `/v1` 与 `/remember` 写入时调 `appendEpisode`（原始消息）；memory 加 `evidence: {episode_id, source_text_snippet}` 字段；digest/insight 加 `source_ids` | ①重启后 `/v1` 跑 10 轮对话，episodes.jsonl 有 10 行；②`GET /memory/:id` 返回 evidence；③digest.source_ids 指向真实记忆 id |
| P0-2 | **冲突队列接线** | extract 提示词输出增加 `fact_key`（规则：住址/职业/宠物名/账号等可变事实给 `主语+属性` 键，其余不输出）；normalize 校验；`/v1` 与 `/remember` 传递 fact_key | ①"他住杭州"→"他搬到上海"两条同 fact_key 自动进 conflicts；②裁决 keep_new 后 recall 只返回新值，问"以前住哪"经 superseded 可查 |
| P0-3 | **手动写入补向量** | `/remember` 路由接入 makeEmbedder（与 /v1 同路径） | 配 Ollama 后手动写的记忆有 vector；不配则向量缺失不报错 |
| P0-4 | **数据迁移**：旧 brain.json 无新字段 | store.load() 缺省补齐 evidence/valid 字段；写迁移说明 | 旧数据文件加载后 /stats 正常，无报错 |
| P0-5 | **分支保护 + CI**：main 禁直推 | GitHub 分支保护（PR + 1 review） | 推 main 被拒，PR 流程通 |

### P1 —— 重要增强（论文机制引入）

| # | 任务 | 论文依据 | 实现 | 验收标准 |
| --- | --- | --- | --- | --- |
| P1-1 | **反思机制**（insight） | Generative Agents 反思树 | nightly 或手动触发：取 retention×importance Top-N 记忆 → LLM 提炼 2-3 条洞察（kind=insight, meta.source_ids=[...]，永不衰减）| 连续 7 天运行后，对"他从这段交往中学到什么"类问题能引用 insight |
| P1-2 | **valid 双时间线** | Zep/Graphiti | memory 加 `valid_from/valid_until`；supersede 时自动 set valid_until=now；recall 支持 `as_of` 参数（查历史状态） | 同 P0-2 数据：`as_of=三个月前` 问住址返回杭州 |
| P1-3 | **关系边复活** | memory-brain extractor | extract 提示词恢复 relations 输出（LLM）+ normalize 校验；入库时 addRelation；检索图谱路改为"共现 + 关系边"双源 | 带 relation 边的记忆 ≥20%；体检图谱计数 >0 |
| P1-4 | **手动写入补向量** | — | /remember 接 makeEmbedder | 配 Ollama 后手写记忆有 vector |
| P1-5 | **小型记忆评测集** | LongMemEval 五维度改造 | scripts/eval.mjs：seed 对话史 → 60 题（事实召回 20/时间推理 10/知识更新 10/多跳关联 10/拒答 10）→ 断言 recall+block 结果 | 输出五维度得分表；拒答题对"没记过的事"召回为空 ≥90% |
| P1-6 | **confidence 字段** | 任务书第十节 | extract 输出 confidence（LLM 自评 + 规则校正）；recall 返回；面板显示 | hypothesis 与低置信记忆在注入时带"（未证实）"前缀 |
| P1-7 | **记忆管理 UI** | 任务书第八节 | 面板加"管理"页签：列表/搜索/查看/编辑/删除/导出/隐私切换（调 API） | 能完成一次"查→改→存"闭环且 audit 留痕 |

### P2 —— 前沿探索（研究型，先实验再默认启用）

| # | 任务 | 论文依据 | 说明 |
| --- | --- | --- | --- |
| P2-1 | 多步图扩散（PPR 近似） | HippoRAG | 把 1 跳共现升级为带衰减的 2-3 步迭代扩散；评测对比 Recall@5 |
| P2-2 | 干扰衰减 | MSR 2026 | 同簇新记忆加速旧记忆淡忘（小系数）；评测确认不误伤 |
| P2-3 | sleep-time 巩固升级 | LightMem | 夜巡增加"主题重组"（把散事件归入主题文件夹视图） |
| P2-4 | 查询改写 | 检索文献 | LLM 把口语查询改写为检索词（与现有 cleanQuery 规则互补） |
| P2-5 | 多模态 attachments | SimpleMem | memory.attachments 引用图片 OCR 结果（配合市场 qq_see/qq_ocr） |
| P2-6 | Memory-R1 式可学习决策 | Memory-R1 | 需训练管线——保持操作原语接口兼容即可，暂不训练 |

### 暂不建议（有理由的拒绝）

| 技术 | 拒绝理由 |
| --- | --- |
| 引入向量数据库服务（Milvus/Qdrant） | 本引擎零依赖是核心卖点；JSON+内存索引在 1 万条内够用，SQLite 分片为后备 |
| 知识编辑 / 参数化记忆 / 测试时训练 | 需要训练模型或访问模型权重，插件层做不到 |
| 全量引入 Graphiti/Neo4j | 部署重、运维成本高；本引擎的关系需求（个人记忆）用实体+关系边已覆盖 |
| 重写成 Python 复用 memory-brain | AGPL 传染 + 放弃零依赖优势 |

## 3. 基准与评测计划（第六阶段蓝本）

| 维度 | 题型 | 数量 | 判定 |
| --- | --- | --- | --- |
| 事实召回 | "我的猫叫什么" | 20 | block 包含正确实体 |
| 时间推理 | "他以前住哪 / 现在住哪" | 10 | as_of 前后各一问 |
| 知识更新 | 冲突裁决后问新值 | 10 | 返回新值且旧值不出现 |
| 多跳关联 | "团子的主人住哪个城市"（团子→主人→城市） | 10 | 需图扩散命中 |
| 拒答 | 从未记过的问题 | 10 | 召回为空或明确说不知道 |
| 成本 | 每轮注入字节 / 夜巡 token | — | 报告 |

执行：`node scripts/eval.mjs` 固定种子生成对话史 → 逐题跑 → 输出 JSON + Markdown 得分表。对比组：原版 / 纯全文 / BM25 / 本引擎混合。**固定同一模型与预算**，分数不与其他论文跨条件比较。

## 4. 依赖关系与工期粗估

```
P0-1 证据链 ──┐
P0-2 冲突接线 ─┼─→ P1-2 双时间线 ──→ P2-1 PPR
P0-3 向量补齐 ─┘   P1-1 反思（依赖 P0-1 证据链）
P0-4 迁移（先行）   P1-3 关系边（独立）
P0-5 分支保护（独立，一次配置）
```
