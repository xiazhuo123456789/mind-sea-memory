## 1. 执行摘要（最值得关注的 8 个结论）

1. **记忆层 vs 运行时之争已收敛**：MemGPT/Letta 证明"记忆需要 OS 式主动管理"，mem0 证明"记忆可以是无侵入的记忆层"。两者都对——本引擎选记忆层路线是对的，但缺少 Letta 式的"记忆自主编辑工具"。
2. **双时间线成为事实更新的标准答案**：Zep/Graphiti 用 `valid_at/invalid_at`（世界时间）+ `created_at/expired_at`（系统时间）双时间线，"换城市"自动失效旧事实但保留历史。本引擎的 `superseded` 状态是它的简化版，缺 `valid_from/valid_until` 字段。
3. **A-MEM 的记忆演化是最接近"理解"的机制**：新记忆写入时 LLM 判断"这会改变哪些旧记忆"，主动更新旧笔记的内容与链接——形成动态语义网络。本引擎的图谱只有静态共现。
4. **LightMem 三阶段（感觉→短期→长期）+ 睡眠巩固**在 LongMemEval 上报告 **token 成本降 ~10.9×、准确率升 ~71.4%**——与本引擎"夜间整理"方向一致，但它多了"感觉记忆过滤层"（写入前的第一道降噪闸）。
5. **Memory-R1 用 RL 学会 ADD/UPDATE/DELETE/NOOP**：记忆管理操作本身可以是被训练的策略，而不是启发式规则。当前不可直接引入（需要训练管线），但它的**操作原语设计**（四操作 + 记忆蒸馏）值得借鉴为接口。
6. **HippoRAG 证明图检索能"单跳实现多跳"**：PPR 在知识图上一次性完成多跳联想，比迭代检索快 10-30×。本引擎的 1 跳共现扩散是它的极简版。
7. **评估基准已成体系**：LoCoMo（超长对话）、LongMemEval（含拒答/知识更新/时间推理）可直接改造为本引擎的回归测试——这是目前最大的短板：**本引擎没有任何记忆质量评测**。
8. **"保留原始事件 + 更新事实视图"成为共识设计**：Generative Agents 的 memory stream、Zep 的 episode 子图、SimpleMem 的语义压缩都遵循"原始记录永不删、压缩视图可重建"。本引擎的 `episodes.jsonl` 存在但**从未被写入**——这是最大的结构性缺陷（详见审查报告）。

## 4. 重点论文深度卡片（10 篇）

> 完整阅读卡片按任务书第七节模板。标注〔摘要级〕的卡片，其"实验数据"栏引用的是论文摘要/第三方转述的数字，未独立复现。

### 卡片 1 · Generative Agents〔精读·机制级〕

- **研究问题**：25 个 Agent 在小镇里生活，如何让它们行为可信而不失忆？
- **记忆定义**：单一 memory stream——所有观察按时间顺序平铺，不分类。
- **数据流**：观察写入 → 检索（recency×importance×relevance 三指数积）→ 语言规划 → **反思**（当某话题累积重要性超过阈值，触发"我最近在想什么"式提问，LLM 从记忆子集提炼 2-3 条高层洞察，**洞察本身也写入记忆流**——形成递归的记忆树）。
- **关键算法**：importance 由 LLM 打 1-10 分（"poem rating"）；relevance 用 embedding 余弦。
- **消融**：去掉 reflection → Agent 的对话具体性/可信度显著下降；去掉 recency → 行为过时。
- **成本**：每 Agent 每轮多次 LLM 调用（反思尤其贵）——论文自己承认成本高。
- **局限**：单 Agent 单用户、无隔离、无遗忘（记忆只增不减）、无冲突处理。
- **对本引擎价值**：**反思机制直接可借鉴**——本引擎有 digest（昨日三件事）但缺"从 N 条记忆提炼模式级洞察（kind=insight）且洞察可回溯源记忆"。风险：反思的 LLM 成本与"洞察是否可靠"需要人工抽查。

### 卡片 2 · MemGPT〔精读·机制级〕

- **研究问题**：有限上下文窗口内如何做长期一致对话？
- **架构**：main context（in-window：system + working context + FIFO 消息）+ external storage（recall storage 全量对话 / archival storage 向量库）；LLM 通过**函数调用自管记忆**（编辑 working context、检索 recall/archival）。
- **关键设计**：上下文满时 LLM 自己决定把什么"分页"到外部；重要信息可主动"core memory 写入"。
- **消融/实验**：在 Document QA 和 multi-session 对话上优于固定窗口基线。
- **局限**：依赖 LLM 严格遵循函数调用协议；记忆编辑的可靠性随模型能力波动。
- **对本引擎价值**：本引擎的 MCP 工具（mem_recall/mem_remember）就是 MemGPT 的 memory functions 思路——已具备。缺的是"working memory（当前会话缓冲）"与长期库的显式分层。

### 卡片 3 · Mem0〔精读·实测过其宣称〕

- **研究问题**：生产环境如何自动维护记忆（不靠用户显式说"记住"）？
- **架构**：对话 → LLM 抽取候选事实 → 与向量库近邻比对 → LLM 决策 **ADD/UPDATE/DELETE/NOOP** → 写入向量存储。
- **实验**（论文自报）：LoCoMo 上 LLM-as-judge 总分超 MemGPT 约 26%、超 OpenAI 记忆约 29%；延迟显著低。
- **注意**：LoCoMo 分数后来被 Letta 公开质疑（评测方法争议）——**不可直接引用分数排序**，机制设计才是可取之处。
- **对本引擎价值**：①"抽取→比对→决策"的写入管线本引擎已有雏形（extract+fact_key 冲突），但决策只有"进冲突队列"没有 ADD/UPDATE 语义；②它证明了"每轮双 LLM 调用（抽取+决策）"在生产上可接受。

### 卡片 4 · Zep/Graphiti〔精读·工程文档〕

- **研究问题**：事实会过时——"Alice 在 Acme 工作"三个月后变成"Alice 在 Beta 工作"，如何既反映现状又保留历史？
- **架构**：bi-temporal 时序知识图。每条事实边带 `valid_at/invalid_at`（世界时间）+ `created_at/expired_at`（系统时间）。新事实到达 → LLM 抽取实体/关系 → 与图上相邻边比对 → **时间重叠则自动 set invalid_at**（新事实赢，旧事实保留可查）。子图分三类：episodic（原始事件）/ semantic（实体事实）/ community（社区聚类）。
- **对本引擎价值**：①本引擎的 `superseded` + 冲突队列是它的手动版——补 `valid_from/valid_until` 字段即对齐；②episodic/semantic 分层对应本引擎"episodes.jsonl + memories"——但 episodes 未接线。

### 卡片 5 · A-MEM〔摘要级+消融结论〕

- **研究问题**：记忆写入后静态不变，导致关联缺失与过时——如何让记忆自己"进化"？
- **机制**：每条记忆 = 一张 Zettelkasten 卡（LLM 生成上下文描述 + 关键词标签）；新卡到达 → LLM 找近邻 → 生成链接；**记忆演化**：新知识触发对旧卡的属性与内容更新（如"他买了 Switch"→ 更新旧卡"他只玩手游"）。
- **消融**：去掉链接与演化（只留 Base Memory）性能下降明显。
- **对本引擎价值**：①本引擎有 entities 共现但**没有显式 links**——A-MEM 的链接是 LLM 生成、有语义的；②"新记忆触发旧记忆更新"正是用户说的"根据新信息修正旧认知"——可做轻量版：新 fact 写入时对同 owner 近邻旧记忆跑一次"是否需要更新"判定。

### 卡片 6 · HippoRAG〔摘要级+机制分析〕

- **机制**：离线——LLM 从语料抽实体建 KG + 邻接向量；在线——查询抽 nodes 作为 PPR 种子 → Personalized PageRank 在图上扩散 → 一次性返回多跳相关子图。仿海马体"新皮层存储 + 海马索引"。
- **实验**（论文自报）：MuSiQue/2WikiMultiHopQA 多跳 QA 上比 RAPTOR/GraphRAG 高最多 ~20%，检索快 10-30×。
- **对本引擎价值**：本引擎图谱路=1 跳共现，是 PPR 的退化版。升级路径：把检索候选的图扩散从"1 跳共现"升级为"带权重衰减的多步扩散"（不需要真 PPR，两三步迭代扩散即可近似）——纯 JS 可实现。

### 卡片 7 · LightMem〔摘要级〕

- **架构**：感觉记忆（廉价模型/规则过滤原始流，**大幅降噪**）→ 短期记忆（主题分组 + 主动预压缩）→ 长期记忆（**sleep-time 离线巩固**，系统空闲时更新）。检索走精排。
- **实验**（论文自报）：LongMemEval 准确率提升 ~71.4%，token 成本降 ~10.9×，响应延迟显著降。
- **对本引擎价值**：①"感觉记忆过滤层"= 本引擎的 looksLikeQuestion/minChars 闸——但它是 LLM/规则混合的**预压缩**，比本引擎只做"跳过"更进取：值得在写入前做主题分组预压缩；②sleep-time 与本引擎 nightly 同构——增加"巩固质量评估"。

### 卡片 8 · Memory-R1〔摘要级〕

- **机制**：把"这条信息对记忆库做什么"建模为 RL 策略（ADD/UPDATE/DELETE/NOOP），以 QA 正确率为 reward 训练；推理时再加 Memory Distillation 选最相关记忆。
- **对本引擎价值**：RL 训练管线超出本引擎范围（**不建议现在引入**），但它的**操作原语**与本引擎对齐（ADD=insert、UPDATE=fact_key 冲突裁决、DELETE=supersede/archived、NOOP=skip）——接口设计已兼容，未来接 RL 或规则决策都不用改存储层。

### 卡片 9 · LongMemEval〔摘要级〕

- **五种能力维度**：信息提取 / 多会话推理 / 时间推理 / 知识更新 / **拒答**（abstention——记得不确定就说不知道）。
- **对本引擎价值**：这就是用户要的"能判断什么时候该检索/能识别不确定信息"的评测形态。本引擎可做一个 50-100 题的小型评测集：用 seed-demo 生成对话史 + 手写五类问题 + 断言召回结果——不需要跑完整 LoCoMo。

### 卡片 10 · Human-Inspired Memory Architecture（MSR 2026）〔摘要级〕

- **机制**：睡眠式巩固、**干扰遗忘**（相似记忆互相干扰而非单纯时间衰减）、engram 成熟度、再巩固（记忆被提取后重新进入不稳定期）、多线索检索。
- **对本引擎价值**：①"干扰遗忘"补足本引擎只按时间衰减的盲区——相似主题的新记忆应加速旧记忆淡忘（nightly 已有合并，可加"被取代次数"进衰减）；②"再巩固"提示：touch 之后给一个短暂的"可变窗口"是反直觉的，暂不引入，标注为 P2 观察项。
