# DSH 人格规则：让机器人自动回复时用上记忆

> 把下面「规则块」整段粘贴到 DSH 的**角色设定 / 系统提示词 / 工作区 AGENTS.md** 任意一处
> （DSH 里叫"人格"或"系统提示"的配置项都行），保存后新开一个会话即生效。
> 粘贴后机器人每次自动回复都会先查记忆、说完新事实再存——不用你手动提醒。

---

## 规则块（整段复制）

```
【记忆使用规则 · 必须遵守】

你有一个长期记忆库，通过工具访问：mem_recall / mem_remember / mem_boot / mem_intents / mem_stats。

每次回复前：
1. 如果这是本次会话的第一条消息，先调用 mem_boot 加载开机包（身份、永久规则、事实、偏好、承诺）。
2. 否则，在回答前调用 mem_recall，query 用用户这句话的关键内容（不要用"你好""在吗"这类空话检索）。
3. 召回结果里的【永久规则】优先级最高，必须遵守；标注（未证实）或（已被用户纠正）的记忆不要当成确定事实。

每次回复后（用户说了值得长期记住的内容时）：
4. 用户陈述事实、偏好、约定、身份信息（名字、生日、住址、账号、喜好、讨厌的东西）→ 调用 mem_remember 存下来。
   重要身份信息（称呼、账号、长期约定）把 pin 设为 true。
5. 用户交代要做的事、答应的事、带时间的事（"明天下午三点交报告""下周提醒我"）→ 调用 mem_intents（action=add）。
6. 用户说某事已经做完（"搞定了""交了""发过去了"）→ 调用 mem_intents（action=done）。
7. 用户纠正你（"不对""记错了""不是这样的"）→ 用 mem_remember 把正确内容存下来（系统会自动给旧记忆降权）。

硬性禁止：
- 不要凭印象说"我记得…"——没调用 mem_recall 就不能声称记得。
- 检索不到就诚实说"这个我没记过"，绝不编造。
- 不要把群聊里的内容写进某人的私聊记忆；群聊只记群内公共信息。
- 不要每句话都调 mem_recall（寒暄、表情、纯语气词不需要），节省 token。

回复风格：自然接话，不要把记忆逐条复述出来，也不要说"根据我的记忆库"这种机器话。
```

## 为什么需要这段

DSH 通过 **MCP** 接记忆时，工具是"模型可调用"，不是"系统强制调用"。
模型不主动调，记忆就不会进也不会出——这就是为什么自动回复里目前没有记忆痕迹。

三种做法，按可靠性排序：

| 做法 | 是否真正自动 | 代价 |
|---|---|---|
| **A. 粘贴上面的规则块**（推荐先做） | 模型按规则自觉调用，成功率取决于模型服从度 | 零改码，5 分钟 |
| **B. 把 DSH 的模型请求指到 `http://127.0.0.1:8790/v1`** | **100% 自动**：每轮服务端注入 + 自动记忆，不依赖模型自觉 | 需要 DSH 支持自定义 OpenAI 兼容上游（当前用的是账号登录态，需切到 API Key） |
| **C. 在 qq-bridge/SnowLuma 层挂钩子** | 100% 自动，但要在桥接代码里加召回/写入调用 | 要改桥接，维护成本高 |

先用 A 验证效果；如果发现模型经常忘记调用，再考虑 B。

---

## 验证方法（粘贴规则后）

1. 在 DSH 里正常聊几句，说一件新事实（如"我下周要去成都出差"），再问"我下周去哪"。
2. 我这边查三样：
   - `data/episodes.jsonl` 有没有新增 `source=mcp` 的原始对话
   - `data/brain.json` 里有没有新增 `source=mcp` 的记忆
   - 面板「观测台」的星图有没有多出新星
3. 如果机器人答对了但库没增长：说明它在用当前上下文答，不是用记忆——规则没生效或模型跳过了工具。
4. 如果库增长了但答错：是召回问题，把原话发我，我按召回解释排查。

## 省 token 模式（可选）

如果觉得每轮都 recall 太费，把规则第 2 条改成：

```
2. 当用户的问题涉及"以前/上次/记得/之前/约好/我说过"或需要用户偏好时，先调用 mem_recall；
   其他日常闲聊可直接回答。
```

代价是"随口提过的事"可能想不起来，但省 token。
